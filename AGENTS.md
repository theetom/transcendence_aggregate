# Repository working instructions

- At the start of every session in this repository, read `WORK_LOG.md` before investigating, proposing changes, or modifying files. If it is too long to read at once, read it in sections and ensure the latest checkpoint is read before proceeding. Follow the current user's instructions where they supersede historical notes.
- Keep `WORK_LOG.md` current as work happens. Every code edit, file addition, deletion, configuration change, and Git operation that changes repository state must be recorded in the same work session. Do not wait for the user to ask or for the session to end.
- Each entry should explain what changed, why, which files were affected, what verification was actually performed, and what remains unfinished. Record failures and canceled actions accurately; do not describe proposed or approved actions as completed unless execution succeeded.
- Before running a command, explain its purpose and effects in plain language. Distinguish reading files, modifying files, staging, committing, and pushing. Explain any required approval clearly.
- Preserve the testing and backend-edit boundaries recorded in the latest work-log checkpoint. Do not treat permission to import a partner's changes as blanket permission to implement backend fixes.
- Before ending a work session, update the checkpoint with the current state and the agreed next steps. If the user asks to stop or wait, do not begin deferred implementation or testing.
